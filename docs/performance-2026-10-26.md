# Производительность 26 октября

Основание: сравнение JFR `vela-1791833482859` (12.10) и `vela-1792522874128` (20.10),
выборки потока рендера. HUD Vela (`HudLayoutService.extractRenderState`) — около 20%
выборок; из них `bounds()` — треть стоимости отрисовки.

## Изменения

- `PngChrome`: панель из девяти частей отправляется одним GUI-элементом вместо 9–17 blit
  (у каждого были push/scale/pop матрицы, поиск текстуры, копия позы, границы). Вершины, UV,
  конвейер `GUI_TEXTURED` и цвет совпадают с прежним blit. Меньше элементов — меньше работы
  в `GuiRenderState.hasIntersection`.
- `VelaDraw.blit`: одиночный квад без изменения стека матриц.
- `VelaDraw.pixelDensity`: без `Math.hypot` для позы без поворота (результат точно |m00|).
- `ModuleRegistry.byId/all`: без `synchronized`, неизменяемый снимок. Вызывается десятки раз
  за кадр (StreamerMode при каждом тексте, RenderTweaks на сущность, камера, небо).
- Watermark: строка, `split` и измерение пересобираются только при изменении FPS/TPS/пинга
  (раньше дважды за кадр, с `String.format`). Координаты и ширина текстовых чипов кэшируются.
- Состояние панелей: один объект на панель вместо трёх карт с упакованными Float/Long.
- Hotkeys: подсчёт циклом вместо трёх stream за кадр.
- ZakoOpt `Feature.flag`: `-Dzakoopt.*` читаются один раз, без конкатенации строк каждый кадр.
- В выпуск вошёл ранее не выпущенный `TerrainAllocationMapMixin` (21.10): ключи —
  `CompiledSectionMesh` с identity hash, открытая адресация безопасна.

Сборка и 441 тест проходят. Игровой прирост не измерен: сравнить `/vela perf start profile` /
`/vela perf stop` в той же сцене.
