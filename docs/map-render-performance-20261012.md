# Карты и поиск материалов: 12 октября

Профиль `vela-1791812630689.jfr`: около 102 секунд, 51934 кадра, среднее 1,94 мс, p95 3,85 мс, p99 4,75 мс, 11 кадров дольше 16,67 мс. Есть девять GC pauses примерно 28–34 мс. Пользователь сообщил о примерно 200 FPS при взгляде на серверное изображение; точное устройство изображения и временная граница эпизода не подтверждены. В профиле присутствуют MapRenderer и ItemFrameRenderer, а также множество табличек. Общие показатели хуже предыдущего замера, но сцены не контролировались: причинный эффект предыдущего изменения по ним не установлен.

## Найденный путь

Minecraft 26.2 `RenderTypeFeatureRenderer.Group.getOrAddDraw` вызывает `drawRenderTypes.indexOf(preparedRenderType)` для каждого нового материала, если допускается объединение и перестановка. Для N различных материалов возникает до N(N−1)/2 проверок. В JFR заметны PreparedRenderType.Texture.equals и ImmutableList.equals. Этот путь используется и картами в рамках; это подтверждённая избыточная работа, но не доказательство причины всей потери FPS.

## Изменение

DrawGroupLookupMixin заменяет только indexOf в этом месте. AppendOnlyRenderIndex запоминает первый индекс полного PreparedRenderType: текстуры, pipeline, target, uniforms и scissor участвуют в исходном equals/hashCode. Исходные условия canReorder и canConsolidate остаются у Minecraft. Draw-списки и их порядок не изменяются; prepare() по-прежнему выполняется каждый раз, поэтому текущие ресурсы не подменяются старыми.

Индекс живёт только вместе с одной группой одного кадра. До 16 элементов используется прежний линейный поиск; свыше 4096 вспомогательный индекс освобождается и используется исходный путь. Ключи штатного PreparedRenderType имеют стабильные equals/hashCode на время группы: ScissorState использует identity, список Texture создаётся prepareTextures. Внешние модификации списков/нестабильных ключей этим контрактом не поддерживаются.

Проверки покрывают равенство первому indexOf, дубликаты, коллизии, null, лимит, реальные PreparedRenderType с разными текстурами/scissor и сокращение числа equality-проверок на 1000 материалах. Это CPU-микропроверка, не игровой FPS-бенчмарк.

## ZakoOpt

Работа исходного OpenGL streaming ring и работа нативного Vulkan — разные пути. В перенесённой ветке 26.2 старый ImmediateRing отсутствует. Возможность оптимизировать upload/synchronization в Vulkan сохраняется, но требует измерений и соблюдения GPU lifetime; старый GL-код не даёт этот эффект автоматически.

Источники: [Khronos buffer streaming](https://wikis.khronos.org/opengl/Buffer_Object_Streaming), [Vulkan profiling](https://docs.vulkan.org/guide/latest/profiling.html).
Утверждение о приросте ×3 на другом устройстве не является критерием корректности данного порта. Следующий локальный A/B: одинаковая неподвижная камера на изображение, по 30 секунд с Zako включённым и выключенным, команды perf start profile / perf stop. Изображение и разрешение не менять, не открывать GUI между start и stop.
