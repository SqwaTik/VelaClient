# Vela: как продолжить работу

Документ для того, кто берётся за проект с нуля: что где лежит, как собирать, проверять, ставить и выпускать, что уже сделано и что осталось. Подробности по коду в [ARCHITECTURE.md](ARCHITECTURE.md), по портам в [PORTING.md](PORTING.md), по сборке из исходников в [SOURCE_BUILD.md](SOURCE_BUILD.md).

## Что это

Vela — клиентский мод для Minecraft 26.2 на Fabric: свой интерфейс, модули, HUD, аккаунты, оптимизации рендера, Vulkan. Интерфейс в первую очередь на русском. К моду есть лаунчер Vela Launcher (Electron), который ставит игру, Fabric и сам мод.

| Что | Где |
|---|---|
| Мод (этот репозиторий) | https://github.com/SqwaTik/VelaClient, ветка по умолчанию `main` |
| Лаунчер | https://github.com/SqwaTik/VelaLauncher, папка `../vela-launcher` |
| Порты на другие версии и NeoForge | ветка `port/multiversion`, рабочая копия `../vela-ports` |

Версии зафиксированы в `gradle.properties`: Minecraft 26.2, Fabric Loader 0.20.1, Fabric API 0.159.0+26.2, Loom 1.17.20, мод `mod_version=0.2.1`.

## Окружение

- **JDK 25.** Gradle сам скачивает его в `~/.gradle/jdks/`, укажи на него `JAVA_HOME`:
  ```bash
  export JAVA_HOME=~/.gradle/jdks/jdk-25.0.4.1+1
  ```
  Для NeoForge 1.21.11 дополнительно нужен JDK 21 (см. PORTING.md).
- **Python 3.10+**, только стандартная библиотека. Всегда запускай с `-I`: `python -I tools/...`.
- **Node.js 20+** для лаунчера.
- `gh` (GitHub CLI) для релизов и PR.
- Файлы пиши с переводом строки **LF**.

## Сборка и проверки

| Команда | Что делает |
|---|---|
| `./gradlew build` | компиляция и юнит-тесты (около 500 тестов), jar в `build/libs/vela-client-0.2.1.jar` |
| `./gradlew verifyClient` | `build` плюс настоящий запуск клиента: аудит всех миксинов, экраны Vela, мир со всеми модулями, замер FPS |
| `./gradlew verifyClient -Pvulkan` | то же на Vulkan |
| `./gradlew sourceBundle` | архив исходников для релиза (`build/distributions/`) |

Флаги игрового теста (`src/gametest/.../VelaClientGameTest.java`):

| Флаг | Что даёт |
|---|---|
| `-Pvulkan` | бэкенд Vulkan вместо OpenGL |
| `-PbenchSize=WxH` | размер окна; по умолчанию 1920x1080, потому что играют в полный экран, а на 854x480 вклад GPU почти не виден |
| `-PfarScene` | сгенерированный мир до горизонта на дальности 24; для работы с дальними чанками |
| `-PcrowdScene` | 48 игроков в броне и стена карт; каждая оптимизация меряется вкл/выкл |
| `-PperfBreakdown` | разбивка времени кадра |
| `-PvisualChecks` | дополнительные визуальные проверки |
| `-Pjfr` | профиль JFR всего прогона в `build/gametest.jfr` |
| `-Prebaseline` | переписать базовую линию FPS |

- **Базовая линия FPS** лежит в `perf/fps-baseline.properties`. История хранится отдельно для каждого размера окна (`history.1920x1080=...`), разные размеры между собой не сравнивают. Цифры относятся к этой машине: на другой машине сделай `-Prebaseline`. Файл не откатывай (`git checkout`), там накопленная история.
- **Набор модулей для замера** — `perf/user-modules.txt`, это реальный игровой профиль.
- **Длинные прогоны.** `-PfarScene` идёт около 17 минут, его запускай в фоне и пиши лог в файл:
  ```bash
  ./gradlew verifyClient -x test -Pvulkan -PfarScene > build/far.log 2>&1
  grep "Vela gametest" build/far.log
  ```
- **Не запускай два прогона одновременно.** Старый процесс игры держит `debug.log`, и следующий прогон падает на `deleteGameTestRunDir`. Если так случилось, закрой зависшие java-процессы clientGameTest.

**Особенности игрового теста:**
- `Minecraft.getInstance()` нельзя звать из потока теста, используй `context.computeOnClient` и `context.runOnClient`.
- `TestInput.resizeWindow` меняет размер только виртуально, а на Vulkan ломает устройство (DEVICE_LOST). Размер задаётся параметрами запуска `--width/--height` в `build.gradle`.
- Сервер шлёт чанки по дальности, которую *запросил* клиент. Если меняешь `renderDistance` из кода, сразу вызывай `mc.options.broadcastOptions()`.

## Установка собранного jar

Перед игрой мод проверяют через `verifyClient`. Потом jar кладут в три места, старые копии предварительно сохраняют в бэкап:

| Метка | Путь | Зачем |
|---|---|---|
| R | `%APPDATA%/.vela/.vela-runtime/vela-client.jar` | рабочая копия, с которой лаунчер запускает игру |
| S | `%LOCALAPPDATA%/Programs/Vela/resources/vela-client.jar` | копия внутри установленного лаунчера |
| L | `../vela-launcher/build/vela-client.jar` | копия, которую лаунчер упаковывает при своей сборке (`extraResources` в его `package.json`) |

```bash
ts=$(date +%Y%m%d-%H%M%S); B="$APPDATA/.vela/mod-backups/manual-$ts"; mkdir -p "$B"
R="$APPDATA/.vela/.vela-runtime/vela-client.jar"; S="$LOCALAPPDATA/Programs/Vela/resources/vela-client.jar"; L="../vela-launcher/build/vela-client.jar"
cp "$R" "$B/R.jar"; cp "$S" "$B/S.jar"; cp "$L" "$B/L.jar"
for d in "$R" "$S" "$L"; do cp build/libs/vela-client-0.2.1.jar "$d"; done
md5sum build/libs/vela-client-0.2.1.jar "$R" "$S" "$L"
```

Все четыре md5 должны совпасть. Откатиться можно из `%APPDATA%/.vela/mod-backups/`.

## Правила работы

**Changelog — при каждом изменении.**
1. Добавь пункт в `src/main/resources/assets/velaclient/changelog.json`, сразу на английском и на русском. Тот же текст игрок видит в игре в «Что нового».
2. Пересобери `CHANGELOG.md`:
   ```bash
   python -I tools/changelog_md.py
   ```
3. Версию сам не поднимай. Сейчас 0.2.1, новая версия появляется только к релизу и по решению владельца.

**Тексты в интерфейсе.**
- Русская строка в Java — это ключ перевода. Для каждой такой строки нужна запись в `src/main/resources/assets/velaclient/lang/en.json` вида `"русский текст": "English text"`.
- Тексты пиши для игрока: что делает функция и что он заметит. Без внутренней кухни и без слов вроде «улучшенный» или «мощный».

**Код.**
- Подстраивайся под окружающий код: его имена, плотность комментариев и стиль.
- Комментарий объясняет, *почему* сделано так (ограничение движка, замер, найденная причина), а не пересказывает код.
- Модули ищи по классу (`Modules.active(X.class)`), а не по id. Подробнее в ARCHITECTURE.md.
- Миксины лежат в `mixin/<группа>/` и регистрируются в `velaclient.mixins.json` как `"группа.Имя"`. Аудит в `verifyClient` проверяет, что у каждого миксина есть цель.
- **Оптимизации:**
  - у каждой есть свой переключатель в настройках оптимизации (`module/Optimization.java`);
  - каждая проверяется замером вкл/выкл в игровом тесте;
  - если у функции есть путь только для OpenGL, при VulkanMod он выключен.
- Встроенные сторонние моды (IAS, Bobby, Mod Menu) лежат исходниками в `src/main/java`, лицензии и список изменений в `THIRD_PARTY.md`.

**Безопасность.**
- Токены Microsoft и любые чужие токены и cookie не публикуются и в обычные конфиги не попадают.
- Системные настройки и настройки безопасности ПК не трогаются.

**Git и GitHub.**
- Коммит делается только тогда, когда владелец просит. Сообщение пиши по делу, как у прошлых коммитов (`Vela client 0.2.1`, `Big fix round: ...`).
- Всё, что видно снаружи (push в `main`, релиз, PR, правка описания репозитория), сначала согласуй с владельцем.
- Удалять репозитории, релизы и теги может только владелец.

## Релиз

Так был сделан v0.2.0:
1. Поднять `mod_version` в `gradle.properties` и добавить новую версию с датой в `changelog.json`.
2. Пересобрать `CHANGELOG.md`.
3. Прогнать `./gradlew verifyClient`, а для изменений рендера ещё и `-Pvulkan`.
4. Сделать коммит `Vela client X.Y.Z` в `main` и запушить.
5. Создать релиз `vX.Y.Z` на `main`. Приложить два файла:
   - `vela-client-X.Y.Z.jar`;
   - `VelaClient-X.Y.Z-sources.zip`: это переименованный `build/distributions/vela-client-source.zip` из `./gradlew sourceBundle`.

   Заголовок `Vela X.Y.Z: <главное>`, описание — разделы «New» и «Fixed» простым языком.
   ```bash
   gh release create vX.Y.Z build/libs/vela-client-X.Y.Z.jar VelaClient-X.Y.Z-sources.zip --target main --title "Vela X.Y.Z: ..." --notes-file notes.md
   ```
6. Лаунчер: в `../vela-launcher` поднять `clientVersion` в `src/shared/constants.ts`, положить jar в `build/vela-client.jar` и выполнить `npm run typecheck && npm run dist`. Свои обновления лаунчер берёт из `releases/latest` репозитория VelaLauncher, поэтому его релиз выпускается отдельно, в том репозитории.

## Что сделано (на 2026-11-04)

**Выпущено:** 0.2.0 опубликован на GitHub. 0.2.1 закоммичен (`b376843`), но релиза на GitHub ещё нет.

**Сделано после 0.2.1, лежит в рабочей копии ветки `fix/framegen-upscaler-shaders-sounds` и не закоммичено:**
- **Быстрая сборка моделей.** Кубы мобов и игроков пишутся в буфер целиком, буквы — целыми глифами (`CubeLayout`, `FastCubes`, `QuadSink`, `GlyphQuadMixin`). Сильно разгружает поток рендера на Vulkan.
- **Атлас карт.** Карты в рамках рисуются из общих текстур 2048x2048 (`MapAtlas`, `MapRendererAtlasMixin`, `MapInstanceUploadMixin`). Одинаковая карта повторно не загружается.
- **Толпы игроков.** Поиск скина по нику больше не гоняет regex на каждом кадре (`NameSkins`).
- **Упрощение дальних чанков.**
  - Дальше 128 блоков листва сплошная, а трава и цветы в сетку не попадают. Когда подходишь ближе, чанк пересобирается.
  - Код: `DistantChunks` и миксины `Distant*`.
  - Замер на 24 чанках, 1920x1080, Vulkan: +28% FPS (213 → 272).
- **Игровой тест.**
  - Окно 1920x1080, история FPS отдельно для каждого размера.
  - Сцена `-PfarScene`: наблюдатель над лесом, дальность отправляется серверу, тест ждёт, пока прогрузится около 1500 чанков.
  - Сцена `-PcrowdScene`.
- **Инструмент портов** `tools/port_mappings.py` и описание к нему `docs/PORTING.md`.

Эти изменения стоит закоммитить и, по решению владельца, выпустить как 0.2.1 или следующую версию.

**Порты, ветка `port/multiversion`** (`../vela-ports`, последний коммит `7d76ff0`, PR пока не открыт). Отдельная сборка `versions/`, по модулю на версию, общий код из `src/` переписывается под каждую:
