# Встроенная FG Vela

## Контракт

FG входит в Vela, отдельный сторонний мод не устанавливается. Переключатель в интерфейсе не предусмотрен. Активация требует совместимого устройства, успешной инициализации, подтверждённого вывода дополнительных кадров и отсутствия измеренного ухудшения. Отсутствие данных не означает успех. OpenGL пока не поддерживается собственным мостом.

## Реализованный участок

- `FgQueueReservation`: собственный консервативный планировщик трёх дополнительных очередей в graphics family. Очереди Minecraft сохраняются. Если места, compute или presentation support не хватает, плана нет.
- `FgQueueMixin`: дополнение запроса очередей до создания устройства; исходная карта не изменяется. Результат кэшируется. Ошибки подготовки записываются в журнал с сохранением обычного запроса.
- `FgDeviceLifecycleMixin` и `FgDeviceSession`: получение разных дескрипторов зарезервированных очередей после создания устройства и сброс при его закрытии. Дескрипторы заимствованы: Vela не уничтожает устройство Minecraft.
- `FgNative`, `vela_jni.cpp`: собственный JNI-протокол версии 1 и проверка FSR runtime. Статусы 0–5 определены в Java: успех, неверный путь, ошибка загрузки, отсутствующие функции, отсутствующий провайдер, внутренняя ошибка. Исключения C++ не пересекают границу JNI. Относительные пути не принимаются. Успешная проверка не включает FG и не создаёт GPU-ресурсов.

## Проверки

Тесты планировщика покрывают доступный запас, точную ёмкость, недостаток очередей, отсутствие возможностей и неверные числа. До реализации тест не компилировался из-за отсутствия класса; после реализации прошёл. ASM-проверка сверяет точки подключения с Minecraft 26.2. Нативный smoke-тест проверяет реальную загрузку `vela_fg.dll`, ABI, null/относительный путь, DLL без API FidelityFX и повторные проверки настоящего runtime.

## Не завершено

### Проверка вывода Vulkan — 20 сентября 2026

Изолированное скрытое окно на RTX 3050 теперь проверяет полный путь синтетической сцены: подготовка глубины и нулевых векторов движения, FSR dispatch через callback, композиция и вывод дополнительных кадров. Каждый цикл сначала выводит 12 кадров без интерполяции, затем 12 с интерполяцией; счётчик реальных present равен 36. Три последовательных создания и уничтожения на одном устройстве проходят Vulkan validation, включая synchronization validation. Это не игровой тест качества или прироста FPS.

В закреплённом SDK устранены обнаруженные проверкой ошибки: двойное создание семафоров; отсутствие освобождения глобальных ресурсов композиции; индивидуальное освобождение descriptor sets из пула без соответствующего флага; использование одного семафора для разных изображений; гонка между завершением GPU и ещё выполняющимся вызовом present на CPU. Изменения сохранены в `native/fidelityfx-v1.1.4-fixes.patch`, сборка проверяет наличие ключевых исправлений. Правило привязки семафора к полученному изображению подтверждено [Vulkan Guide](https://docs.vulkan.org/guide/latest/swapchain_semaphore_reuse.html).

Команда регрессии: `native/test-surface.ps1`. Ошибки и предупреждения Vulkan приводят к ненулевому результату теста. Последовательное ожидание каждого кадра в этом тесте предназначено для проверки владения ресурсами и не подходит для игрового цикла. Перекрывающиеся swapchain, смена устройства, resize, потеря устройства и качество движения пока не проверены. Глобальные кеши SDK пока ограничивают многопоточную работу нескольких swapchain.

DLL пока используется отдельным smoke-тестом и не загружается автоматически клиентом. Её упаковка, проверка включённых возможностей устройства, управление FSR-контекстом на устройстве Minecraft, замена swapchain, захват мира/HUD, векторы движения, вывод и автоматическая оценка производительности ещё не реализованы. Очереди подготовлены, но в них не отправляется работа. Изменённая сборка не установлена в рабочий клиент. Игровой запуск с новыми mixin ещё не проверен.

Следующий участок должен подтвердить расширения и возможности, реально включённые при создании устройства, до создания FSR-контекста. Поддержка физическим GPU недостаточна. Перед заменой swapchain обязательны владение ресурсами, синхронизация и обработка resize/RP/shutdown; тест создания контекста не заменяет эту проверку.
